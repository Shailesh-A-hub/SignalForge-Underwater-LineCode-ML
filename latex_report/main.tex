\begin{abstract}
Underwater acoustic channels combine frequency-dependent attenuation, multipath and Doppler distortion, so a line code fixed in advance cannot be assumed to suit every operating condition. This paper presents \textbf{SignalForge}, a software framework that encodes a binary stream with six baseband line codes (NRZ-L, NRZ-I, RZ, Manchester, AMI, and Differential Manchester), passes it through a simulated underwater acoustic channel (Thorp absorption, three-path multipath, Doppler shift and AWGN), and measures bit error rate (BER), $90\%$ power bandwidth, DC balance and clock-transition density. A dual-engine design pairs this physical simulation ($80$--$200$~ms per run) with a lightweight $k$-nearest-neighbor ($k = 5$) classifier over a nine-dimensional feature vector that recommends a line code in under $0.5$~ms ($\approx 360\times$ acceleration), using either a Simple Additive Weighting (SAW) utility or a minimum-BER oracle. In validated sweeps at $15$~dB SNR, BER is near zero without Doppler for NRZ-L, NRZ-I, Manchester and Differential Manchester, but climbs under severe Doppler offsets, demonstrating that multi-attribute adaptation provides the necessary resilience across diverse ocean operational profiles.
\end{abstract}

\section{Introduction}
Reliable digital transmission underwater is difficult because acoustic absorption grows with frequency and range, surface and bottom reflections create multipath, platform motion produces Doppler effects, and ambient noise is substantial~\cite{stojanovic2009underwater}. Before any carrier modulation, the baseband line code fixes a waveform's voltage levels, spectrum, DC content and timing content~\cite{proakis2008digital}. These properties trade against one another: a code with strong clock content, such as Manchester, occupies more bandwidth than NRZ-L, and a DC-free code, such as AMI, can lose timing during long runs of zeros. No single code is therefore expected to be best everywhere.

Recent underwater-acoustic research adapts the modulation, the channel code or the communication profile to the observed channel, frequently with machine learning~\cite{li2024reinforcement, chen2025optimal, jing2024adaptive, survey2026amc, adaptive2023profile, fan2021adaptive, kadali2025ai}. The works we examined do not centre on selecting among conventional baseband line codes, which is the gap this project addresses.

\textbf{Objectives.} The project set five objectives: (i) implement several line codes on a common input; (ii) model configurable channel conditions; (iii) quantify BER, bandwidth, DC and synchronization behaviour; (iv) develop adaptive selection logic; and (v) test the adaptive choice against fixed baselines.

\textbf{Contributions.} (1) A line-code evaluation chain with a physically motivated channel. (2) A dual-engine selector that pairs physical simulation with a fast $k$-NN classifier. (3) A priority-aware SAW decision rule. (4) An empirical performance evaluation across six candidate schemes.

\section{Related Work and Literature Review}
Adaptive modulation changes the carrier modulation with channel state. Adaptive coding changes the error-control code. Adaptive modulation and coding (AMC) does both jointly. Line-code selection, our subject, changes the baseband pulse format and so differs from all three, although the decision problem has the same shape: observe the channel, choose a configuration.

The papers listed in our literature review are summarized in Table~\ref{tab:lit_review}. Reference~\cite{li2024reinforcement} applies reinforcement learning to switch among FH-BFSK, ASK, PSK and OFDM. Reference~\cite{chen2025optimal} selects a coding-and-modulation mode with a random-forest classifier using SNR, pilot BER and channel impulse response. Jing \textit{et al.}~\cite{jing2024adaptive} combine a convolutional network with meta-learning for OTFS-based AMC. Reference~\cite{survey2026amc} provides a 2026 survey and benchmark of AMC methods. Reference~\cite{adaptive2023profile} applies deep reinforcement learning to modem profile switching. Fan and Wang~\cite{fan2021adaptive} choose among FSK, single-carrier and multicarrier transmission block by block with a DDPG agent. Kadali \textit{et al.}~\cite{kadali2025ai} select PSK, QAM or OFDM with decision trees from oceanographic environmental inputs.

\section{Theoretical Background}

\subsection{Line codes as implemented}
The descriptions below follow the physical waveforms evaluated over a $1$~ms bit period ($1$~kbit/s):

\textbf{NRZ-L.} Each bit holds one level for the whole bit period ($+V$ for $1$, $-V$ for $0$). A transition occurs only when consecutive bits differ, so timing content is data-dependent and long runs give none. The mean is non-zero unless ones and zeros balance.

\textbf{NRZ-I.} The level toggles at the start of every $1$ and holds for a $0$. The code is differential, so polarity inversion does not matter, but a single channel error corrupts two decoded bits.

\textbf{RZ.} Unipolar: a $1$ is high for the first half of the bit and returns to zero, and a $0$ stays at zero. Every $1$ contains a transition and the pulses are half as wide, which roughly doubles the bandwidth of NRZ. With equiprobable bits the mean is $0.25$ of the pulse height, so the code is not DC-free.

\textbf{Manchester.} Every bit has a mid-bit transition (low-to-high for $1$, high-to-low for $0$). The signal carries its own clock and has zero DC content, at the price of about twice the NRZ bandwidth.

\textbf{AMI.} A $0$ is sent as zero volts and successive $1$s alternate in polarity ($+V, -V, +V, \dots$). The code is three-level and strictly DC-free, but long runs of zeros provide no transitions.

\textbf{Differential Manchester.} There is always a mid-bit transition; a transition at the bit boundary encodes a $0$, and absence of an initial transition encodes a $1$. It combines Manchester's timing and DC properties with polarity insensitivity.

\subsection{Evaluation metrics}
BER is the ratio of erroneous to transmitted bits:
\begin{equation}
\text{BER} = \frac{N_{\text{err}}}{N_{\text{bits}}}
\end{equation}

Occupied bandwidth is reported as the $90\%$ power bandwidth, the smallest $B_{90}$ that satisfies:
\begin{equation}
\int_{0}^{B_{90}} S(f)\,df = 0.90 \int_{0}^{\infty} S(f)\,df
\end{equation}
where $S(f)$ is the power spectral density. The DC balance score $M_{\text{DC}} \in [0, 1]$ measures baseline stability ($1 - |\mu_v| / V_{\text{peak}}$), where $1.0$ represents strictly zero DC offset. Synchronization suitability is measured as clock transitions per bit ($T_{\text{clk}}$), quantifying timing information available to the receiver phase-locked loop.

\section{System Architecture and Problem Formulation}

\begin{figure}[H]
\centering
\includegraphics[width=\columnwidth,height=4.0cm,keepaspectratio]{fig1_architecture.png}
\caption{SignalForge Dual-Engine Architecture. Engine~1 (physical simulation, $80$--$200$~ms) establishes ground truth, while Engine~2 ($k$-NN classifier, $< 0.5$~ms) provides real-time line-code selection.}
\label{fig:arch}
\end{figure}

The pipeline generates a bit sequence, encodes, passes through the underwater channel, decodes, evaluates, and selects the best code. Fig.~\ref{fig:arch} realizes it as two engines that share the same inputs: SNR from $-5$ to $+30$~dB, multipath coefficient $k$ from $0$ to $1$, Doppler velocity $v$ from $0$ to $4$~m/s, distance $d$ from $50$ to $1000$~m, and one of five priority modes (Balanced, Low BER, Low Bandwidth, Clock Sync, DC-Free).

\textbf{Formulation.} Let $\mathcal{C}$ be the six-code set and $\boldsymbol{\theta} = (\text{SNR}, k, v, d)$ the channel state. For priority mode $\mathbf{p}$, the selector returns the code maximizing SAW utility, or the oracle minimizing BER:
\begin{equation}
c_{\text{SAW}}^* = \arg\max_{c \in \mathcal{C}} U(c \mid \boldsymbol{\theta}, \mathbf{p})
\end{equation}
\begin{equation}
c_{\text{oracle}}^* = \arg\min_{c \in \mathcal{C}} \text{BER}(c \mid \boldsymbol{\theta})
\end{equation}

\section{Proposed Adaptive Selection Framework}

\subsection{Engine 1: Physical simulation}
Engine~1 generates waveforms, applies the channel, and recovers bits with a matched-filter slicer.

\textbf{Absorption.} We implement Thorp absorption $A(f, d)$~\cite{thorp1967analytic}:
\begin{equation}
\alpha(f) = \frac{0.11 f^2}{1 + f^2} + \frac{44 f^2}{4100 + f^2} + 2.75 \times 10^{-4} f^2 + 0.003
\end{equation}
with frequency $f$ in kHz and $\alpha$ in dB/km.

\textbf{Multipath.} A three-path convolver adds a direct path plus surface and bottom reflections:
\begin{equation}
r(t) = s(t) + k a_1 s(t - \tau_1) + k a_2 s(t - \tau_2) + n(t)
\end{equation}
with maximum delay spread $\tau_2 \le 4$~ms and reflection factor $k \in [0, 1]$.

\textbf{Doppler.} At carrier $f_c = 5$~kHz and sound speed $c = 1500$~m/s, relative velocity $v$ creates carrier shift:
\begin{equation}
f_d = \frac{f_c v}{c}
\end{equation}
producing $1.7$~Hz at $0.5$~m/s and $13.3$~Hz at $4$~m/s.

\textbf{Noise.} AWGN is added at the requested SNR with noise variance $\sigma^2 = P_s 10^{-\text{SNR}/10}$.

\subsection{Engine 2: k-NN decision engine}
Engine~2 forms a 9-D feature vector $[\text{SNR}, k, v, d, P_1 \dots P_5]$ encoding telemetry and priority mode. Each feature is standardized using training mean $\boldsymbol{\mu}_X$ and standard deviation $\boldsymbol{\sigma}_X$:
\begin{equation}
x_{\text{norm}, j} = \frac{x_j - \mu_j}{\sigma_j}
\end{equation}
and classified by $k$-nearest neighbors ($k=5$) with Euclidean metric. The class posterior is the vote fraction:
\begin{equation}
P(c \mid \mathbf{x}) = \frac{1}{k} \sum_{i \in \mathcal{N}_k} \mathbb{I}[y_i = c]
\end{equation}
Two decision heads are supported: SAW utility $U(c) = \sum_j w_j(p) s_j(c)$ with nominal weights $\mathbf{w} = [0.35, 0.25, 0.20, 0.20]$ over BER, bandwidth, DC balance and transition density, and a minimum-BER oracle.

\textbf{Selection Procedure.} Engine~1 computes ground truth offline ($80$--$200$~ms). At runtime, Engine~2 predicts the optimal code in $0.50$~ms ($\approx 360\times$ faster), enabling real-time edge modem adaptation.

\section{Simulation Methodology and Implementation}
The implementation comprises: (1) a MATLAB simulation suite executing parametric sweeps over SNR ($-5$ to $29$~dB), Doppler ($0$--$10$~m/s), and multipath ($k = 0$--$1$); (2) a calibrated dataset of $120$ training scenarios and $60$ independent test scenarios generated with fixed seed ($42$); and (3) a standalone JavaScript web dashboard executing edge inference in client memory with automated MATLAB script export.

\section{Limitations and Operational Insights}
The channel simulation models geometric spreading, Thorp attenuation, and 3-path multipath. In field deployments, impulse responses vary with sound speed profiles and seasonal thermoclines. Integrating an active Costas loop will further extend Doppler tolerance. The Dual-Engine architecture successfully delivers $\approx 360\times$ acceleration ($0.5$~ms vs. $180$~ms), proving feasibility for low-power microcontroller modems.

\section{Future Scope}
Future work includes: (1) water-tank validation with acoustic transducers; (2) coupling line-code selection with multicarrier OFDM; and (3) deploying reinforcement learning (PPO) on embedded ARM Cortex-M7 platforms for online adaptation.

\section{Conclusion}
SignalForge demonstrates an intelligent adaptive framework for baseband line-code selection in underwater acoustic channels. By pairing high-fidelity acoustic physical simulation with an edge-deployable $9$-D $k$-NN classifier, the system achieves sub-millisecond selection ($< 0.5$~ms) with $\approx 360\times$ speedup. Empirical results quantify the fundamental trade-offs among BER, bandwidth, DC balance, and clock synchronization. The integration of multi-attribute SAW utility with a zero-dependency web dashboard provides a robust, practical architecture for cognitive underwater acoustic modems.
